# Knowledge Bot — извлечение знаний из каналов

Telegram-бот для VPS: кидаешь ему ссылку на публичный **Telegram-канал**,
**YouTube-канал** или **стену ВКонтакте** — он выкачивает посты/видео (для YouTube
берёт субтитры), прогоняет их через нейросеть (**DeepSeek**) и достаёт **факты**,
**ссылки на исследования**, **техники**, **рекомендации/лайфхаки** и **интересную
информацию**. Всё складывается в локальную базу («память») и выгружается в
Markdown-файлы.

> Instagram — следующий этап.

## Как это работает

```
  Ты в личке боту:  https://t.me/...  или  https://youtube.com/@...
            │
            ▼
   ┌────────────────────── VPS ──────────────────────┐
   │  Telethon-бот   ── интерфейс (команды, ответы)    │
   │      │                                            │
   │  Telegram: userbot (Telethon) ── история канала   │
   │  YouTube:  yt-dlp + субтитры  ── расшифровки видео │
   │  VK:       wall.get (VK API)  ── посты стены       │
   │      │                                            │
   │  DeepSeek API   ── извлечение знаний → JSON        │
   │      │                                            │
   │  SQLite («память») + экспорт в Markdown           │
   └──────────────────────────────────────────────────┘
            │
            ▼
   Бот присылает: facts.md / research.md / techniques.md / ...
```

**Зачем userbot отдельно от бота?** Обычный бот (Bot API) не может читать историю
чужого Telegram-канала — только там, где он админ. Поэтому чтение идёт через userbot
(твой аккаунт, Telethon), а бот отвечает за интерфейс. Для YouTube аккаунт не нужен:
список видео берётся через `yt-dlp`, текст — из субтитров (`youtube-transcript-api`).
Для ВК нужен только токен (`VK_ACCESS_TOKEN`) — посты тянутся методом `wall.get`.

## Установка на VPS

```bash
git clone <repo> /opt/knowledgebot
cd /opt/knowledgebot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
nano .env            # заполнить ключи (см. ниже)
```

### Что положить в `.env`

| Переменная | Где взять |
|---|---|
| `TG_API_ID`, `TG_API_HASH` | https://my.telegram.org → API development tools |
| `TG_BOT_TOKEN` | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `ALLOWED_USER_IDS` | твой Telegram id у [@userinfobot](https://t.me/userinfobot) |
| `DEEPSEEK_API_KEY` | https://platform.deepseek.com |
| `VK_ACCESS_TOKEN` | https://dev.vk.com → приложение → сервисный ключ (для ВК) |

### Первый вход userbot (один раз)

```bash
python login.py     # спросит номер телефона и код из Telegram
```

Создастся `data/userbot.session`. После этого можно запускать бота.

### Запуск

```bash
python main.py
```

Напиши боту в личку — пришли ссылку на канал.

### Автозапуск через systemd

```bash
sudo cp deploy/knowledgebot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now knowledgebot
journalctl -u knowledgebot -f      # логи
```

## Команды бота

| Команда | Что делает |
|---|---|
| ссылка на TG/YouTube-канал | разобрать свежие записи и прислать выжимку |
| `/full <ссылка>` | выкачать **весь архив** канала целиком |
| `/list` | какие каналы уже разобраны и сколько пунктов |
| `/digest <канал>` | прислать выжимку по каналу заново |
| `/search <слово>` | поиск по всей накопленной базе |

Платформа определяется по ссылке: `youtube.com`/`youtu.be` → YouTube,
`vk.com` → ВКонтакте, иначе Telegram. YouTube и ВК указывай ссылкой
(`https://youtube.com/@handle`, `https://vk.com/public123`), Telegram — ссылкой,
`@именем` или просто именем.

## Как устроен мониторинг и глубина разбора

База помнит `last_message_id` каждого канала. При первом разборе по ссылке берутся
последние `INITIAL_FETCH_LIMIT` постов (по умолчанию 150) — это потолок только для
**первого** прохода, чтобы быстро ответить и не упереться во flood-wait Telegram.
При повторной отправке той же ссылки добираются **только новые посты** (без лимита).

Нужен весь архив канала целиком — команда `/full <канал>`: она тянет всю историю,
пропуская уже сохранённые посты (так что повторный `/full` лишь дозаберёт старый
бэклог, не переплачивая за повторное извлечение). Стоит дёшево: даже 5000 постов на
DeepSeek-Flash ≈ $0.3.

Так что «следить за каналом» = время от времени присылать боту ту же ссылку (или
повесить напоминание/cron, который дёргает разбор — добавим позже).

## Выбор модели

По умолчанию `DEEPSEEK_MODEL=deepseek-chat` (актуальная чат-модель DeepSeek,
OpenAI-совместимый API). Задача «вытащить факты/техники» простая, поэтому
дорогую модель брать не нужно. Сменить модель/провайдера — одна строка в `.env`
(`DEEPSEEK_MODEL`, `DEEPSEEK_BASE_URL`, `DEEPSEEK_API_KEY`), код менять не надо.

## Структура

```
main.py                 точка входа (запуск бота)
login.py                одноразовый вход userbot
app/
  config.py             конфиг из .env
  bot.py                интерфейс + оркестрация (роутинг по платформе)
  collector.py          сбор постов Telegram (Telethon)
  youtube.py            сбор видео YouTube (yt-dlp + субтитры)
  vk.py                 сбор постов ВКонтакте (wall.get)
  extractor.py          извлечение знаний (DeepSeek)
  prompts.py            промпты и категории
  db.py                 SQLite-хранилище (мультиплатформенное)
  markdown_export.py    экспорт в Markdown
deploy/
  knowledgebot.service  unit для systemd
```

## Ограничения / честные оговорки

- Только **публичные** каналы.
- YouTube: текст берётся из **субтитров**. Если у видео их нет — оно пропускается
  (распознавание аудио через Whisper — следующий этап). Дата видео во flat-списке
  не приходит, поэтому в выжимке у YouTube-пунктов даты может не быть.
- Категория «исследования» наполняется лишь тем, что **явно упомянуто** в тексте —
  модель проинструктирована не выдумывать источники. Но проверять первоисточники
  всё равно стоит.
- Скрейпинг контента может противоречить правилам платформы — для личного
  использования обычно ок, для продукта оцени риски сам.
